# Photo Select AI — Windows v0.3.9 Portrait + Groups

Локальная программа для research/evaluation. Доступны **два режима**:

- **Portrait** — один лучший кадр из серии одного ребёнка → **RED**.
- **Group** — один главный групповой кадр → **RED**, плюс до **3** дополнительных кандидатов для ручной перестановки голов → **YELLOW**.


## v0.3.9 — разделение групп по составу детей

Исправлена важная ошибка группового режима: раньше предварительная серия делилась в основном по паузе между файлами. Если фотограф быстро переходил к следующей группе, десятки разных групп могли попасть в один временной блок и анализироваться как одна серия.

Теперь внутри каждого временного блока выполняется отдельное разбиение по **смене состава распознанных детей**. Для решения о границе используется только identity embedding InsightFace; положение ребёнка в кадре не считается доказательством совпадения группы. Потенциальная новая группа должна быть подтверждена следующим кадром, поэтому одиночный плохой embedding не создаёт ложную границу.

Повторное объединение через длинную паузу стало консервативнее: требуется устойчивое совпадение большей части identity на нескольких граничных кадрах, а не один наиболее удачный pair.

В итоговой статистике добавлено `Найдено границ по смене состава детей`.

## v0.3.8 — portable-функционал удалён

Встроенной portable-сборки больше нет: удалены PyInstaller builder, portable self-test, вопрос в `install.bat`, fallback на portable из `run.bat` и связанные тесты. Это упрощает установку и поддержку.

### Перенос на другой компьютер

`runtime\venv` **не считается переносимым окружением**. Python официально рекомендует virtual environment удалять и пересоздавать в целевом месте, а не копировать как готовый runtime. Поэтому надёжный перенос выглядит так:

```text
1. Скопировать всю папку Photo Select AI на другой Windows-компьютер.
2. Запустить там install.bat.
3. Установщик создаст/проверит локальный runtime\venv, CUDA runtime и InsightFace-модели.
4. После этого использовать run.bat.
```

Сам проект, конфигурацию и модели можно копировать. Если вместе с папкой приехал старый `runtime\venv`, не следует полагаться на него как на переносимый Python; при проблемах его лучше удалить и заново запустить `install.bat`.

## Главное изменение v0.3.5 — независимые правила Portrait / Group

Портретный алгоритм и его профили **не изменены**. Group mode теперь хранит и применяет собственный профиль правил независимо от портретного режима. Переключение режима не перезаписывает веса портрета.

Рекомендуемый групповой профиль — **«Глаза прежде всего»**:

- количество детей с уверенно открытыми глазами — первичный критерий выбора RED;
- остальные критерии используются после сравнения глаз;
- если есть ребёнок с закрытыми глазами, целевой YELLOW ищется только для того же identity с открытыми глазами;
- по умолчанию `YELLOW минимум = 1`, поэтому даже без формального дефекта сохраняется один сильный резервный дубль;
- `YELLOW максимум = 3`.

Дополнительные групповые профили: **«Сбалансированный»** и **«Больше резервных кадров»**. Эти правила не влияют на Portrait.

## Главное изменение v0.3.4 — YELLOW по конкретному ребёнку и открытым глазам

В групповом режиме закрытые/прикрытые глаза теперь являются отдельной проблемой и не скрываются средним quality score лица. Если на RED у ребёнка глаза закрыты, YELLOW-кандидат ищется только среди кадров **того же identity-track**, где глаза действительно открыты. Кадр с тем же ребёнком, но всё ещё прикрытыми глазами, не считается решением.

Главный RED также получил отдельный штраф за количество детей с закрытыми глазами, поэтому при прочих равных выбирается дубль, где больше детей смотрят с открытыми глазами. В журнал добавлена диагностика: проблемы глаз/отсутствия лица/резкости/качества, сколько проблем закрыто YELLOW и сколько осталось без подходящего дубля.

## Главное изменение v0.3.3 — полный прогресс и без итогового popup

В групповом режиме шкала прогресса теперь отражает не только CUDA-анализ фотографий, но и дальнейшую обработку: поиск групповых серий, объединение частей одной физической группы, сопоставление детей, построение треков, оценку покрытия, выбор RED/YELLOW и запись XMP. 100% появляется только после полного завершения обработки.

Отдельное окно статистики после анализа больше не показывается. Краткий итог остаётся в строке состояния, полная статистика — в правой панели журнала.

## Главное изменение v0.3.2 — исправление Windows batch-файлов

`install.bat`, `run.bat` и служебные `.bat` теперь распространяются без UTF-8 BOM и с CRLF. Это предотвращает строку `я╗┐@echo off` и вывод каждой выполняемой команды в Windows CMD.

- **журнал перенесён вправо** в отдельную изменяемую панель;

### Профили поиска серий

- **Сбалансированный** — рекомендуемый вариант для большинства съёмок 3–20 кадров на ребёнка.
- **Меньше повторов** — чуть активнее объединяет соседние фрагменты одного ребёнка.
- **Строже к случайным кадрам** — требует больше подтверждений лица и лучше отбрасывает стены, пол, отражения и одиночные false-positive.
- **Чувствительнее к сложным лицам** — снижает пороги и увеличивает detector input для дальних, профильных и частично закрытых лиц.
- **Пользовательский** — появляется автоматически, если вручную изменить связанные расширенные параметры.

### Профили выбора лучшего кадра

- **Сбалансированный** — глаза и резкость имеют высокий приоритет, выражение и улыбка учитываются умеренно.
- **Глаза и фокус** — более строгий приоритет открытых глаз и точности фокуса.
- **Выражение и улыбка** — сильнее учитывает выражение лица и улыбку.
- **Без приоритета улыбки** — улыбка не влияет на рейтинг.
- **Пользовательский** — появляется автоматически при ручной настройке весов.

Точные веса глаз, резкости, выражения и улыбки по-прежнему доступны на отдельной вкладке **«Критерии выбора»**.

### Расширенные настройки

DBSCAN, пороги детектора, временные границы, размер preview и параметры CUDA скрыты по умолчанию. Они появляются только после включения:

## Алгоритм серий (ядро v0.2.5)

После перехода на InsightFace детекция лиц стала заметно стабильнее, но на реальной съёмке проявились две другие проблемы:

- один ребёнок иногда разбивался на 2–3 соседние серии и получал несколько RED;
- одиночная ложная детекция на стене, полу, зеркале или случайном кадре могла превратиться в отдельную серию.

Логика серий двухступенчатая:

```text
файлы по времени/имени
        ↓
InsightFace SCRFD + ArcFace embedding
        ↓
строгий DBSCAN (по умолчанию distance 0.27)
        ↓
объединение только соседних фрагментов
того же ребёнка (по умолчанию distance 0.32)
        ↓
проверка доказательств серии:
минимум 2 уверенных обнаружения лица
        ↓
объединение того же ребёнка через короткую паузу
между соседними временными блоками
        ↓
1 RED на итоговую серию
```

Это гистерезис: строгий порог отвечает за разделение похожих детей, а немного более мягкий применяется **только к соседним уже найденным фрагментам**. Поэтому для уменьшения дублей больше не требуется просто повышать DBSCAN distance для всей съёмки.

Правило из исходного ТЗ сохраняется:

```text
ребёнок A → ребёнок B → ребёнок A
```

остаётся тремя отдельными сериями. Объединение никогда не перепрыгивает через подтверждённую серию другого ребёнка.

## Защита от стены / пола / случайного кадра

SCRFD по-прежнему работает с мягким порогом (по умолчанию `0.25`), чтобы не потерять сложное лицо. Но **новая серия** должна отдельно получить подтверждение:

```text
Порог подтверждения лица:              0.45
Мин. уверенных кадров для новой серии: 2
Мин. площадь подтверждающего лица:     0.05 %
```

Поэтому единичный false positive детектора не становится серией. Для реальной съёмки, где типичная серия содержит 3–20 кадров, минимум 2 подтверждения является рекомендуемым значением.

Если у вас действительно бывают одиночные портреты, параметр можно установить в `1`.

## Повторные тесты и старые RED-метки

Предыдущие версии добавляли новые RED-метки, но не снимали результаты старых запусков. После нескольких тестов Adobe Bridge мог показывать одновременно выборы разных версий алгоритма.

В быстром старте есть:

```text
[✓] Перед анализом снять старые RED-метки
```

При включённой опции программа удаляет **только текущее имя RED label** (например `Select`) и затем выполняет новый анализ. Остальные XMP-поля, Camera Raw настройки и рейтинги сохраняются.

Если вы вручную используете ту же красную метку до запуска программы и не хотите её снимать — выключите параметр.

Для JPG сначала проверяется только заголовок JPEG; весь большой файл перечитывается и переписывается только когда старая целевая метка действительно найдена.

## InsightFace

Весь анализ лица построен на одном InsightFace model pack `buffalo_l`:

```text
SCRFD             → поиск лица
recognition model → embedding ребёнка
2d106det           → 106 landmarks глаз/рта
OpenCV/Numpy       → резкость лица/глаз и технические метрики
```

Старого MediaPipe backend в проекте больше нет.

## Расширенные → «Серии и лица»

У каждого числового параметра есть `ⓘ`/HelpTip: **минимум**, **максимум**, рекомендуемое значение и объяснение эффекта увеличения/уменьшения.

### DBSCAN distance

- диапазон: `0.10–0.60`;
- рекомендуется: `0.25–0.30`;
- по умолчанию: `0.27`.

Это **строгий первичный** порог. Не рекомендуется повышать его только ради устранения дублей одного ребёнка — для этого теперь есть отдельный параметр объединения соседних фрагментов.

### Дистанция объединения соседних фрагментов

- диапазон: `0.20–0.50`;
- рекомендуется: `0.30–0.34`;
- по умолчанию: `0.32`.

Больше → лучше соединяет профиль/анфас одного ребёнка, которые DBSCAN разделил.

Слишком большое значение → может объединить двух очень похожих детей, поэтому этот порог применяется только к соседним фрагментам.

### Мин. уверенных кадров для новой серии

- диапазон: `1–6`;
- рекомендуется: `2`;
- по умолчанию: `2`.

Главный регулятор ложных серий. Если случайные стены/зеркала всё ещё появляются — сначала увеличьте этот параметр до `3`.

### Порог подтверждения лица

- диапазон: `0.20–0.90`;
- рекомендуется: `0.40–0.55`;
- по умолчанию: `0.45`.

Это не SCRFD detection threshold. Низкий SCRFD threshold нужен для полноты поиска, а этот более высокий порог решает, достаточно ли надёжно лицо для **создания новой серии**.

### Допуск кадров без embedding

- диапазон: `0–8`;
- рекомендуется: `2–4`;
- по умолчанию: `3`.

Пропущенный/смазанный кадр внутри уже подтверждённого ребёнка не разрывает серию, если тот же ребёнок распознан с обеих сторон.

Кадры без лица в начале или конце блока теперь не присоединяются к ребёнку автоматически.

### Объединять того же ребёнка через паузу

- диапазон: `0–180 с`;
- рекомендуется: `30–60 с`;
- по умолчанию: `45 с`.

Если длинная пауза или скачок номера файла разорвали съёмку одного ребёнка на два грубых временных блока, два **соседних** блока могут быть объединены обратно по ArcFace embedding.

`0` отключает этот механизм.

### Дистанция объединения через паузу

- диапазон: `0.15–0.45`;
- рекомендуется: `0.27–0.31`;
- по умолчанию: `0.30`.

Если один ребёнок по-прежнему выбирается дважды именно после паузы, слегка увеличивайте этот параметр. Если склеиваются два похожих ребёнка — уменьшайте.

## Рекомендуемые параметры первого теста

```text
DBSCAN distance:                         0.27
DBSCAN минимум кадров:                   2
Дистанция соседнего объединения:         0.32
Мин. уверенных кадров:                   2
Порог подтверждения лица:                0.45
Мин. площадь подтверждающего лица:       0.05 %
Допуск без embedding:                    3

Макс. пауза грубого блока:              12 сек
Объединять того же ребёнка через паузу: 45 сек
Дистанция объединения через паузу:       0.30
Мин. кадров итоговой серии:              2

SCRFD threshold:                         0.25
Detector size:                           640
```

Если **один ребёнок выбирается несколько раз**:

1. сначала `Дистанция соседнего объединения 0.32 → 0.34`;
2. если дубль возникает после длинной паузы — `Дистанция через паузу 0.30 → 0.32`;
3. DBSCAN `0.27` менять только после этого.

Если появляются **случайные серии**:

1. `Мин. уверенных кадров 2 → 3`;
2. затем `Порог подтверждения 0.45 → 0.50`;
3. только затем повышать основной SCRFD threshold.

Так полнота обнаружения детей страдает меньше.

## Вкладка «Критерии выбора»

Каждый критерий имеет независимый вес `0.00–3.00`. Вес `0` полностью исключает критерий.

По умолчанию:

```text
Открытые глаза — обязательный фильтр: ВКЛ
Порог открытых глаз:                  0.52
Вес открытых глаз:                    1.80
Штраф закрытых глаз:                  0.45
Вес резкости глаз:                    1.40
Вес резкости лица:                    0.90
Вес выражения лица:                   0.70
Вес улыбки:                           0.35
Вес технического качества:           0.35
```

## CUDA / RTX 5090

Рекомендуемый режим:

```text
InsightFace provider: auto
cuDNN Conv:           HEURISTIC
```

Сборка использует ONNX Runtime GPU 1.26.0 и ветку CUDA 12.8/cuDNN 9.24. Установщик после установки прогоняет detector, recognition и landmarks на CUDA.

Если включена защитная опция CUDA → CPU и реальный CUDA runtime падает, весь InsightFace пересоздаётся один раз на CPU и текущий кадр повторяется; кадр не пропускается.

## Установка

1. Распакуйте архив поверх предыдущей версии или в новую папку.
2. Запустите `install.bat`.
3. При HTTPS-перехвате Kaspersky можно выбрать `2 — Kaspersky compatibility mode`.
4. После установки окно ждёт нажатия клавиши и не закрывается автоматически.
5. Запустите `run.bat`.

Можно передать каталог сразу:

```bat
run.bat "D:\Photos\Shoot"
```

CLI:

```bat
run.bat "D:\Photos\Shoot" --cli
```
